# Каскад (Waterfall) и Agile на примере «Автостоянки»

Одна и та же программа сделана двумя способами. Смотреть историю:
```
git log --graph --oneline --all
git log --oneline waterfall
git log --oneline main
```

| | Каскад (ветка `waterfall`) | Agile (ветка `main`) |
|---|---|---|
| Порядок работы | этапы строго друг за другом: требования, проект, код, тесты, приёмка | три коротких спринта, в каждом понемногу всего сразу |
| Требования | все описаны заранее (docs/tz.md) и не меняются | backlog, его можно менять между спринтами (docs/backlog.md) |
| Когда появляется код | на 3-м из 5 этапов, сразу весь | в каждом спринте, понемногу |
| Когда появляются тесты | отдельным этапом после кода | вместе с кодом в том же спринте |
| Первая рабочая версия | только в конце (v1.0) | после 1-го спринта (v0.1), потом v0.2, v1.0 |
| Коммиты | 5 крупных | много мелких |
| Ветки | одна линия | feature-ветка и слияние |
| Итог работы | docs/sprints.md нет, есть этапы | docs/sprints.md: что сделали и что поняли в каждом спринте |

**Плюсы каскада:** понятный план и документы. **Минус:** ошибку в требованиях найдут поздно.
**Плюсы Agile:** рабочая версия рано, можно менять планы. **Минус:** сложнее заранее сказать, когда всё будет готово.
